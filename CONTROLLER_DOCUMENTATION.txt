ASYNCHANDLER UTILITY:
─────────────────────
Location: backend/src/utils/asyncHandler.ts

Purpose: Wraps async functions to catch errors automatically
Function: Converts thrown errors into JSON responses

Example Usage:
  export const functionName = asyncHandler(async (req, res) => {
    // Your async code here - errors are caught automatically
  });

Why Use It:
- Prevents "unhandled promise rejection" crashes
- Automatically sends error responses to client
- Reduces try-catch boilerplate code
- All controller functions use this wrapper


FORMATRESPONSE UTILITY:
──────────────────────
Location: backend/src/utils/formatResponse.ts

Purpose: Creates consistent JSON responses across the API

Usage Pattern:
  formatResponse(data, "Success message")
  formatResponse(null, "Error message")

Response Structure:
  {
    "status": "success" or "error",
    "message": "Your message here",
    "data": { ... actual data ... }
  }

All responses go through formatResponse to ensure consistency


EXPRESS REQUEST/RESPONSE OBJECTS:
──────────────────────────────────
req = Request object (incoming data from client)
  - req.body = Data sent in POST/PUT body
  - req.params = URL parameters (e.g., /resume/:resumeId)
  - req.query = Query string parameters (e.g., ?page=1&limit=10)
  - req.user = Authenticated user info (set by auth middleware)
  - req.cookies = Cookies sent by client
  - req.headers = HTTP headers

res = Response object (what we send back)
  - res.status(200) = HTTP status code
  - res.json() = Send JSON response
  - res.send() = Send binary data
  - res.setHeader() = Set response header
  - res.cookie() = Set cookie in response
  - res.clearCookie() = Remove cookie


MONGODB & MONGOOSE OPERATIONS:
────────────────────────────────
These are used throughout controllers:

.findById(id) = Find document by ID
.findOne({field: value}) = Find first document matching condition
.find({conditions}) = Find all documents matching conditions
.create({data}) = Create and save new document
.findByIdAndUpdate(id, {updates}, {new: true}) = Update document
.findByIdAndDelete(id) = Delete document
.countDocuments({conditions}) = Count matching documents
.populate(field) = Load referenced data from other collection
.select(fields) = Choose which fields to return
.skip(n) = Skip first n documents
.limit(n) = Limit to n documents
.sort({field: 1 or -1}) = Sort ascending (1) or descending (-1)

Example:
  const resume = await Resume.findById(resumeId);  // Get one resume
  const resumes = await Resume.find({userId: userId}).limit(10);  // Get many


AUTHENTICATION PATTERN:
───────────────────────
req.user._id = ID of logged-in user (set by auth middleware)

Used to:
- Filter data by user (show only their resumes, cover letters, etc.)
- Prevent unauthorized access (verify document belongs to user)
- Track who created/modified data


AUTHORIZATION PATTERN:
──────────────────────
Common pattern in controllers:

  const userId = req.user._id;
  const document = await Model.findById(documentId);
  
  // Verify user owns this document
  if (document.userId.toString() !== userId.toString()) {
    return res.status(403).json(formatResponse(null, "Unauthorized"));
  }

Why .toString()?
- MongoDB IDs are ObjectId type, not regular strings
- Must convert both sides to strings for comparison
- Example: ObjectId("123") !== ObjectId("123") (different instances)
- But: ObjectId("123").toString() === ObjectId("123").toString() (same string)


PAGINATION PATTERN:
──────────────────
Used in all "list" endpoints:

  const { page = 1, limit = 10 } = req.query;
  const skip = (page - 1) * limit;
  
  const items = await Model.find().skip(skip).limit(limit);
  const total = await Model.countDocuments();
  const pages = Math.ceil(total / limit);
  
  return res.json(formatResponse(
    { items, total, pages },
    "Items retrieved"
  ));

Example:
- Page 1, limit 10:  0, get items 0-9
- Page 2, limit 10: skip 10, get items 10-19
- Page 3, limit 10: skip 20, get items 20-29


DATE OPERATIONS:
────────────────
new Date() = Current date and time
new Date(startDate) = Parse date string to Date object

MongoDB Date Queries:
  { createdAt: { $gte: startDate, $lte: endDate } }
  $gte = greater than or equal (>=)
  $lte = less than or equal (<=)

Aggregation Pipeline Dates:
  { $dateToString: { format: "%Y-%m-%d", date: "$createdAt" } }
  Groups data by date string (YYYY-MM-DD)


MONGODB AGGREGATION:
─────────────────────
Advanced queries using pipeline stages:

  Model.aggregate([
    { $match: { condition } },        // Filter documents
    { $group: { _id: field, count: { $sum: 1 } } },  // Group & aggregate
    { $sort: { _id: 1 } },             // Sort results
    { $limit: 10 }                     // Limit results
  ])

Common $group aggregations:
  { $sum: 1 } = Count documents
  { $sum: "$field" } = Sum values of field
  { $avg: "$field" } = Average of field
  { $max: "$field" } = Maximum value

11. SEARCH RESUMES
────────────────────
Function: searchResumes(req, res)
HTTP Method: GET /api/resumes/search?query=javascript&page=1
Response: Array of matching resumes

Key Concept - REGEX (Regular Expression):
$regex = MongoDB pattern matching
$options: "i" = case-insensitive

Logic:
- Get search query from query parameter
- Search two fields: title and extractedText
- $or = match if EITHER field contains search term
- $regex = pattern matching (not exact match)
- "i" option = case insensitive

Example Query:
  { $or: [
      { title: { $regex: "java", $options: "i" } },      // Match "Java", "JAVA", "java"
      { extractedText: { $regex: "java", $options: "i" } }
    ]}

Returns: Paginated search results

3. AUTHENTICATION CONTROLLER - LOGIN/REGISTER
═══════════════════════════════════════════════════════════════════════════════

File: backend/src/controllers/auth.controller.ts

Functions:
──────────

1. REGISTER
────────────
Function: register(req, res)
HTTP Method: POST /api/auth/register
Input: { email, password, name, phoneNumber }
Response: 201 Created

Key Concept - PASSWORD HASHING:
Never store plain passwords!
- Use bcrypt to hash passwords
- authService.register() hashes the password
- Database stores hashed version
- Only hashed version sent back to anyone

Logic:
- Check if email already exists (prevent duplicates)
- If exists, return 400 error
- Call authService.register() to create user (hashes password)
- Generate JWT access token (short-lived, ~1 hour)
- Generate refresh token (long-lived, ~7 days)
- Set refresh token in HTTP-only cookie (secure storage)
- Return access token + user data to client


Key Concept - JWT (JSON Web Token):
Format: header.payload.signature
- Stateless authentication (no server session needed)
- Payload contains userId and expiry time
- Signature prevents tampering
- Client sends token in Authorization header
- Server validates signature before accepting


Key Concept - HTTP-ONLY COOKIE:
- Cookie can't be accessed by JavaScript (prevents XSS attacks)
- Browser automatically includes in all requests
- Server can validate refresh token from cookie
- Used to issue new access tokens


2. LOGIN
─────────
Function: login(req, res)
HTTP Method: POST /api/auth/login
Input: { email, password }
Response: 200 OK

Logic:
- Find user by email
- If not found, return 401 Unauthorized
- Use authService.comparePassword() to verify password
  - Compares plain password with stored hash
  - Returns true/false
- If password invalid, return 401 Unauthorized
- Generate tokens (access + refresh) same as register
- Set refresh token cookie
- Return access token + user data


3. LOGOUT
──────────
Function: logout(req, res)
HTTP Method: POST /api/auth/logout
Response: 200 OK

Logic:
- Clear refresh token cookie
- Client should also delete access token from storage
- Next requests won't have valid token


4. REFRESH TOKEN
──────────────────
Function: refreshToken(req, res)
HTTP Method: POST /api/auth/refresh-token
Response: 200 OK

Purpose: Get new access token when it expires

Logic:
- Extract refreshToken from cookies
- If not found, return 401 Unauthorized
- Verify refresh token signature
  - authService.verifyRefreshToken() checks if valid
  - Prevents use of expired or tampered tokens
- Extract userId from token
- Generate new access token
- Return new access token


5. VERIFY EMAIL
────────────────
Function: verifyEmail(req, res)
HTTP Method: POST /api/auth/verify-email
Input: { token }
Response: 200 OK

Logic:
- Verify email token (sent in email link)

7. RESET PASSWORD
──────────────────

10. GENERATE REFERRAL LINK
──────────────────────────────
Function: generateReferralLink(req, res)
HTTP Method: GET /api/users/referral-link
Response: 200 OK

Key Concept - BUFFER:
Buffer in Node.js = Binary data container
Buffer.from(string) = Convert string to bytes
.toString("base64") = Encode bytes as base64 string

base64 = Safe encoding for URLs (only alphanumeric + /+=)

Logic:
- Get userId from authenticated request
- Convert userId to string
- Encode to base64 (makes it URL-safe)
- Create referral link with base64 code
- Return link to frontend


Example:
userId = "507f1f77bcf86cd799439011"
Buffer.from(userId).toString("base64") = "NTA3ZjFmNzdiY2Y4NmNkNzk5NDM5MDEx"
Link: http://localhost:3000/auth/register?ref=NTA3ZjFmNzdiY2Y4NmNkNzk5NDM5MDEx

9. IMPORTANT SYNTAX EXPLANATIONS
═══════════════════════════════════════════════════════════════════════════════

ASYNC/AWAIT:
─────────────
What is async?
- Allows writing asynchronous code that looks synchronous
- Prevents "callback hell"
- Pauses execution until async operation completes

async function = can use await inside
await = pause until Promise resolves

Example:
  // WITHOUT await - returns Promise immediately
  const promise = Model.findById(id);  // Returns immediately
  console.log(promise);  // Prints: Promise {...}
  
  // WITH await - waits for Promise to resolve
  const document = await Model.findById(id);  // Waits for result
  console.log(document);  // Prints: actual document data


TRY/CATCH:
──────────
Purpose: Handle errors in async code

Pattern:
  try {
    // Code that might throw error
    const result = await riskyOperation();
  } catch (error) {
    // Handle error
    console.log(error.message);
  }

In our app:
- asyncHandler wrapper handles try/catch for us
- We don't need manual try/catch in most cases


ARROW FUNCTIONS:
─────────────────
Arrow function syntax:
  (params) => { body }

Examples:
  // No params
  () => { return 42; }
  
  // One param
  (x) => { return x * 2; }
  
  // Multiple params
  (x, y) => { return x + y; }
  
  // Implicit return (no braces)
  (x) => x * 2

In controllers:
  export const functionName = asyncHandler(async (req, res) => {
    // body
  });


DESTRUCTURING:
────────────────
Extract values from objects/arrays

Object destructuring:
  const { email, password, name } = req.body;
  // Instead of: const email = req.body.email; ...
  
Array destructuring:
  const [first, second] = [1, 2, 3];
  // first = 1, second = 2


DEFAULT PARAMETERS:
────────────────────
Provide default value if not passed

Example:
  const { page = 1, limit = 10 } = req.query;
  // If page not provided, use 1
  // If limit not provided, use 10


TEMPLATE LITERALS:
───────────────────
Use backticks to embed variables in strings

Syntax:
  `string with ${variable}`

Example:
  const filename = `${resume.title}.${format}`;
  // If title="MyResume", format="pdf"
  // Result: "MyResume.pdf"


SPREAD OPERATOR:
──────────────────
... = spread or rest operator

Usage 1: Copy object
  const copy = { ...original };

Usage 2: Merge objects
  const merged = { ...obj1, ...obj2 };

Usage 3: Rest parameters
  function sum(...numbers) {
    // numbers = array of all arguments
  }


TERNARY OPERATOR:
───────────────────
Short form of if/else

Syntax:
  condition ? trueValue : falseValue

Example:
  const status = user.isActive ? "active" : "inactive";


OPTIONAL CHAINING:
────────────────────
Safely access nested properties

Syntax:
  obj?.property  // Returns undefined if obj is null/undefined
  arr?.[0]       // Returns undefined if arr is null/undefined

Example:
  const rating = user?.profile?.rating;
  // If user exists, get user.profile.rating
  // If user doesn't exist, return undefined (no error)


NULLISH COALESCING:
─────────────────────
Use default value if null/undefined

Syntax:
  value ?? default

Example:
  const count = data?.length ?? 0;
  // If data.length is falsy or null, use 0


LOGICAL OPERATORS:
────────────────────
&& = AND operator
||  = OR operator
!   = NOT operator

Example:
  if (user && user.isActive) { ... }     // Both must be true
  if (hasPermission || isAdmin) { ... }  // Either can be true
  if (!user.isDeleted) { ... }           // Must be false


REGEX PATTERNS:
────────────────
Regular expressions for pattern matching

Syntax: /.../flags

Common flags:
  i = case-insensitive
  g = global (match all, not just first)
  m = multiline

In MongoDB:
  { $regex: "pattern", $options: "i" }  // Case-insensitive match


JSON OPERATIONS:
──────────────────
JSON.stringify(obj) = Convert object to JSON string
JSON.parse(string) = Convert JSON string to object

Example:
  const data = { name: "John", age: 30 };
  const json = JSON.stringify(data);  // '{"name":"John","age":30}'
  const obj = JSON.parse(json);       // { name: "John", age: 30 }


BUFFER:
─────────
Buffer = Binary data container

Common operations:
  Buffer.from(string) = Create buffer from string
  Buffer.from(string, "base64") = Decode base64
  buffer.toString() = Convert to string
  buffer.toString("base64") = Encode as base64

Example:
  const userId = "507f1f77bcf86cd799439011";
  const encoded = Buffer.from(userId).toString("base64");
  // Result: "NTA3ZjFmNzdiY2Y4NmNkNzk5NDM5MDEx"
  
  const decoded = Buffer.from(encoded, "base64").toString();
  // Result: "507f1f77bcf86cd799439011"


HTTP STATUS CODES:
────────────────────
Common codes in our app:

1xx Informational:
  100 Continue

2xx Success:
  200 OK - Request succeeded
  201 Created - Resource created successfully
  204 No Content - Success but no content to return

3xx Redirection:
  301 Moved Permanently
  302 Found (temporary redirect)

4xx Client Error:
  400 Bad Request - Invalid input
  401 Unauthorized - Not authenticated
  403 Forbidden - Authenticated but not authorized
  404 Not Found - Resource doesn't exist
  429 Too Many Requests - Rate limited

5xx Server Error:
  500 Internal Server Error
  502 Bad Gateway
  503 Service Unavailable


HTTP HEADERS:
───────────────
Common headers we set:

Content-Type:
  "application/json" = JSON response
  "application/pdf" = PDF file
  "application/vnd.openxmlformats-officedocument.wordprocessingml.document" = DOCX file
  "text/html" = HTML response

Content-Disposition:
  "attachment; filename=..." = Trigger download
  "inline" = Display in browser

Authorization:
  "Bearer <token>" = JWT authentication token

10. COMMON PATTERNS & BEST PRACTICES
═══════════════════════════════════════════════════════════════════════════════

PATTERN 1: CRUD OPERATIONS
────────────────────────────
Standard pattern for all resources:

  // CREATE
  export const createItem = asyncHandler(async (req, res) => {
    const item = await Model.create(req.body);
    return res.status(201).json(formatResponse(item, "Created"));
  });
  
  // READ ONE
  export const getItem = asyncHandler(async (req, res) => {
    const item = await Model.findById(req.params.itemId);
    if (!item) return res.status(404).json(formatResponse(null, "Not found"));
    return res.status(200).json(formatResponse(item, "Retrieved"));
  });
  
  // READ ALL
  export const getItems = asyncHandler(async (req, res) => {
    const items = await Model.find().limit(10);
    return res.status(200).json(formatResponse(items, "Retrieved"));
  });
  
  // UPDATE
  export const updateItem = asyncHandler(async (req, res) => {
    const item = await Model.findByIdAndUpdate(req.params.id, req.body, {new: true});
    return res.status(200).json(formatResponse(item, "Updated"));
  });
  
  // DELETE
  export const deleteItem = asyncHandler(async (req, res) => {
    await Model.findByIdAndDelete(req.params.id);
    return res.status(200).json(formatResponse(null, "Deleted"));
  });


PATTERN 2: AUTHORIZATION CHECK
─────────────────────────────────
Used in update/delete to prevent unauthorized access:

  const userId = req.user._id;
  const document = await Model.findById(documentId);
  
  if (!document || document.userId.toString() !== userId.toString()) {
    return res.status(403).json(formatResponse(null, "Unauthorized"));
  }
  
  // Proceed with operation


PATTERN 3: PAGINATION
───────────────────────
Used in all list endpoints:

  const { page = 1, limit = 10 } = req.query;
  const skip = (page - 1) * limit;
  
  const items = await Model.find().skip(skip).limit(limit);
  const total = await Model.countDocuments();
  
  return res.status(200).json(formatResponse(
    { items, total, pages: Math.ceil(total / limit) },
    "Retrieved"
  ));


PATTERN 4: SEARCH WITH REGEX
──────────────────────────────
Used for text search:

  const query = req.query.search;
  
  const results = await Model.find({
    $or: [
      { field1: { $regex: query, $options: "i" } },
      { field2: { $regex: query, $options: "i" } }
    ]
  });
  
  return res.status(200).json(formatResponse(results, "Search results"));


PATTERN 5: DATE FILTERING
────────────────────────────
Used for date range queries:

  const { startDate, endDate } = req.query;
  
  let filter = {};
  if (startDate && endDate) {
    filter.createdAt = {
      $gte: new Date(startDate),
      $lte: new Date(endDate)
    };
  }
  
  const results = await Model.find(filter);
  return res.status(200).json(formatResponse(results, "Retrieved"));


PATTERN 6: NESTED POPULATION
──────────────────────────────
Load related documents:

  const user = await User.findById(userId)
    .populate("subscriptionId")
    .populate("resumeIds");
  
  // subscriptionId and resumeIds are now full documents, not just IDs


PATTERN 7: FIELD SELECTION
─────────────────────────────
Choose which fields to return:

  // Exclude password
  const user = await User.findById(id).select("-password");
  
  // Include only specific fields
  const user = await User.findById(id).select("name email");


PATTERN 8: AGGREGATION PIPELINE
──────────────────────────────────
Complex queries with multiple stages:

  const stats = await Model.aggregate([
    { $match: { status: "active" } },
    { $group: { _id: "$category", count: { $sum: 1 } } },
    { $sort: { count: -1 } },
    { $limit: 10 }
  ]);


PATTERN 9: ERROR HANDLING
────────────────────────────
Proper error responses:

  if (!resource) {
    return res.status(404).json(formatResponse(null, "Not found"));
  }
  
  if (unauthorized) {
    return res.status(403).json(formatResponse(null, "Unauthorized"));
  }
  
  if (invalidInput) {
    return res.status(400).json(formatResponse(null, "Invalid input"));
  }


PATTERN 10: AUDIT LOGGING
────────────────────────────
Track important actions:

  await AdminLog.create({
    adminId: req.user._id,
    action: "USER_UPDATED",
    targetUserId: userId,
    details: JSON.stringify({ changes })
  });
